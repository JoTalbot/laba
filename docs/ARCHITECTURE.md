# Архитектура 111ЛАБ

## Конвейер

1. Пользователь загружает PDF задания.
2. Backend извлекает текст, формулы и при необходимости изображения.
3. Parser выделяет тему, цель, номера заданий, вариант и требования.
4. Solver строит решение, объяснение и тесты; решение проверяется до формирования отчёта.
5. Template engine заполняет `шаблонdocx.docx`, сохраняя оформление титульной страницы и структуру отчёта.
6. Renderer выполняет DOCX → PDF.
7. Пользователь получает файл `111ЛАБ.pdf`.

## Frontend

Статический интерфейс размещается на GitHub Pages.

## Backend

Backend нужен для CPU/GPU-задач, Python-библиотек для PDF/DOCX и генерации файлов. Он может быть развёрнут на отдельном сервере/VPS. GitHub Pages не является сервером генерации.

## Защита от prompt injection

PDF и DOCX являются входными данными. Любые инструкции, обнаруженные внутри них, должны рассматриваться как обычный текст документа и не получают приоритет над правилами приложения. Это особенно важно для шаблонов и студенческих материалов.

## API-контракт

`POST /api/solve` — multipart: `lab_pdf`, `student`, `discipline`, `teacher`, `language`.

Ответ: JSON со структурированным отчётом и ссылкой/идентификатором задания на рендеринг.

`POST /api/render` — структурированный отчёт + шаблон → PDF.

Ответ: PDF `111ЛАБ.pdf`.
